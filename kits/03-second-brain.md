> 約 50 分鐘（可以分兩次）｜ Codex、Claude Code 都能用 ｜ Mac、Windows 都能用 ｜ 前提：在你的 `xxx-agent` 資料夾開對話，資料夾裡有 `AGENTS.md`
> 做完你會有：一張**知識地圖**（你的工作需要哪些知識、現在各在哪裡）、第二大腦的三層架構，和你的第一頁知識。

## 給 AI：你要做什麼

你是這位使用者的數位員工。這份檔案做兩件事：

1. **第一段 · 知識地圖**：陪他想清楚「你要把哪件工作做好，需要知道什麼」，再一起找出這些知識現在在哪裡。
2. **第二段 · 第一頁知識**：把最值得的一份原料，整理成第二大腦的第一頁。

**多數人答不出「你有哪些公司知識」，也不知道為什麼要整理。** 所以不要從檔案問起，要從他想交給你的工作問起。他知道這件事對他有什麼用，自己就會開始找。

**八條規矩**

1. **一次只問一題。** 有能點選的提問工具（Codex 的 `request_user_input`、Claude Code 的 `AskUserQuestion`）就用；沒有就列「1. 2. 3.」，結尾寫「回我數字，或直接打字也可以」。**不要為了點選工具去改設定。** 每題最多 4 個選項，最後一個永遠是「其他（我自己說）」。
2. **選項要從他的工作現場長出來。** 用 `AGENTS.md` 和日記裡他講過的話來寫選項，不要給人人都適用的通用選項。
3. **你先猜，他來改。** 能先寫出草稿的，就先寫出來給他改，不要用一連串問題逼他從零想。
4. **用他的原話。** 他說的詞照記，不要換成漂亮話。
5. **看檔案要先問，而且只看他同意的資料夾。** 盤點時只看檔名、類型、修改日期，**不打開內容**。不要掃整台電腦。
6. **不搬、不改、不刪他的檔案。** 要用的原料**複製一份**進 `raw/`，原檔留在原地。
7. **只動這個資料夾裡的東西。** 不裝東西、不改設定。指令跑不了就換備援，還是不行就請他把檔案拖進對話，不要卡住。
8. **每做一步，用一句話講為什麼。** 要像同事在解釋，不要念規格。「盤點」「執行流程」這種詞不要對他說，這份檔案的「第幾步」標題也不要念出來。

**一定要講的一件事（第 3 步開始前）：** 你打開來讀的檔案內容，會送到這個 AI 服務去處理。所以薪資、個資、合約、客戶名單這類資料，要他確認公司規定允許才能給你。只看檔名不會打開內容，但檔名也會出現在這段對話裡。

## 第 0 步 · 先讀（只讀，不要問他）

- 讀 `AGENTS.md`（記下他的稱呼、工作、最想交給你的事、回話的樣子）
- 讀 `memory/daily/` 最近兩篇日記，找「今天找到的場景」或他提過的工作（沒有也沒關係）
- 看 `knowledge/`、`raw/` 有沒有東西，有 `knowledge/knowledge-map.md` 就直接跳到它的「下一步」接著做，不要重來
- `knowledge/` 裡如果有課堂練習用的蜂癒資料（`healingbee-product-handbook`、`customer-reply-style` 這類），那不是他公司的知識：不要放進地圖，開場提一句「上午練習的蜂癒資料可以留著，也可以刪掉，不影響這次」
- 判斷系統：路徑 `/Users/…` 是 Mac，`C:`、`D:` 開頭是 Windows。下面的指令跑對的那一組
- 目前資料夾**沒有 `AGENTS.md`** → 只說這段然後停：
  > 我在這個資料夾找不到我的規則檔 `AGENTS.md`。請**選你的 `xxx-agent` 資料夾開新對話**，再貼一次剛剛那段話。

照 `AGENTS.md` 裡寫的稱呼和回話方式跟他說話。

# 第一段 · 知識地圖

## 第 1 步 · 先講為什麼（一段話，然後問第 1 題）

> 想像我是今天剛到職的同事。你想把 [他的工作或場景，用他的話] 交給我，第一天你會叫我先看什麼？
>
> 現在的我，很會寫，但**不知道你們公司的事**，每開一次新對話，你就要重講一次。我們接下來要做的事，就是讓你**不用再重講**：你們公司的知識，我整理成一頁一頁，要用的時候自己查，而且越用越厚。這叫**第二大腦**。
>
> 你不用先知道自己有哪些資料。我先問你想把什麼工作交給我，再一起找。

## 第 2 步 · 從工作問到知識（三題，一次一題）

**Q1 · 目的**：「你最想先讓我做好哪一件工作？」

選項用他的場景卡或 `AGENTS.md` 寫。答完用一句話接住，例如「所以我要能代你回客戶的詢價，這個當目標」。

**Q2 · 做錯的代價**：「這件事，我如果不知道你們公司的情況，**最可能做錯什麼**？」

你先猜 3 個，寫成他工作裡真的會發生的事（例如「報了舊價格」「答應了做不到的交期」）。這一題是為了讓他看到**為什麼值得整理**，答完講一句：「那這幾件，就是我最需要先知道的。」

**Q3 · 需要的知識**：「要做好這件事，我需要知道哪些？」（可複選）

你先列 4–6 類，用他的工作講，例如「各產品的價格和折扣上限」「客戶最常問的十個問題」。他勾完、補完，這就是知識地圖的第一欄。

## 第 3 步 · 這些知識現在在哪

先講規矩（一段話）：

> 接下來一類一類問你「這個現在在哪」。不知道也沒關係，**「不知道」本身就是有用的答案**。
>
> 有的在電腦裡，我可以幫你找，但**只看檔名和日期，不打開內容，也不搬任何東西**。你讓我打開來讀的檔案，內容會送到這個 AI 服務處理，所以薪資、個資、合約這類資料，要先確認公司規定允許。

Q3 勾的每一類問一題（一次一題）：「[這一類知識] 現在在哪？」選項固定是這四個，只把例子換成他的工作：

1. **電腦裡的檔案**：我告訴你資料夾，或把資料夾拖進來
2. **雲端或別的系統**：Google Drive、公司系統、LINE 群組
3. **在人的腦袋裡**：我自己知道，或要問某位同事
4. **不知道／可能沒有**

答「電腦裡」但說不出在哪，就問：

> 我可以幫你看「桌面、文件、下載」這三個資料夾的**檔名**，不打開內容。可以嗎？

他同意才看。

### 怎麼看資料夾（只列檔名、類型、日期，最多 200 個）

```bash
# Mac（把 FOLDER 換成他給的路徑）
find "FOLDER" -maxdepth 3 -type f \( -iname '*.pdf' -o -iname '*.doc*' -o -iname '*.xls*' -o -iname '*.ppt*' -o -iname '*.md' -o -iname '*.txt' -o -iname '*.csv' -o -iname '*.pages' -o -iname '*.numbers' -o -iname '*.key' \) -not -path '*/.*' -not -path '*/node_modules/*' -exec stat -f '%Sm  %N' -t '%Y-%m-%d' {} + 2>/dev/null | sort -r | head -200
```

```powershell
# Windows（把 FOLDER 換成他給的路徑）
Get-ChildItem "FOLDER" -Recurse -Depth 3 -File -Include *.pdf,*.doc*,*.xls*,*.ppt*,*.md,*.txt,*.csv -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 200 @{n='日期';e={$_.LastWriteTime.ToString('yyyy-MM-dd')}},FullName
```

**備援**：指令跑不了 → 請他把資料夾裡的檔案列表截圖，或直接把檔案拖進對話。

看完**不要把整串貼給他**，只挑跟 Q3 有關的：

> 我看到這幾個可能是你要的。你看看哪些對、哪些是舊版：
> - `2026 報價單_final2.xlsx`（3 週前改過）：像是「價格」
> - `報價單.xlsx`（去年）：**名字很像，可能是舊版，要確認**

**也列一兩個他沒提到、但跟目標可能有關的檔案**，問他要不要加進去。很多人是在這裡才發現：原來我有這份。

**檔名出現薪資、身分證、個資、合約、客戶名單、密碼、帳號這類字眼**：不打開，在地圖標「先不要給我」，跟他說一聲為什麼。

## 第 4 步 · 寫成知識地圖

先寫草稿給他看，他說好才存到 `knowledge/knowledge-map.md`（沒有 `knowledge/` 就建）：

```markdown
# 我的知識地圖

> 目標：[Q1，用他的話]
> 為什麼要做：[Q2，用他的話]

| 我需要的知識 | 現在在哪 | 找到的檔案 | 狀態 | 可以給 AI 嗎 |
|---|---|---|---|---|
| 各產品的價格 | 電腦 | 2026 報價單_final2.xlsx | 有，要確認是不是最新 | 可以 |
| 客戶常問的問題 | 你的腦袋 | 無 | 沒寫下來，我可以訪談你 | 可以 |

## 第一份要做哪個
[第 5 步填]

## 還不知道的
- [他答不知道的，和要問同事的]

## 下一步
- [ ] [第 5 步填]
```

存好後講一句：

> 這張地圖本身就有用：你現在看得到自己的工作**需要什麼、缺什麼**。很多公司的知識只在某個人腦袋裡，寫不出來的地方，就是你最該先處理的地方。

## 第 5 步 · 挑第一份

你先選一份，說明為什麼，他來改。怎麼選：

- **我最常會用到**（跟 Q1 那件工作最相關）
- **做錯代價高**（跟 Q2 有關）
- **現在就拿得到，而且可以給 AI**
- **只在他腦袋裡的也算**：可以當場訪談他，把訪談存成原料

> 我建議從 [這一份] 開始，因為 [一句話]。可以嗎？

他同意後，把選擇寫進地圖的「第一份要做哪個」和「下一步」。

問一題要不要接著做：

1. 接著做第一頁知識（推薦，大約 25 分鐘）
2. 先到這裡，地圖已經存好，下次回來說「接著做第二大腦」

選 2：照「收尾」寫日記，結束。

# 第二段 · 第一頁知識

## 第 6 步 · 講三層，建好架子

> 第二大腦有三層，這是 Karpathy 的方法：
>
> - **`raw/` 原料**：你的原始檔案。我只讀不改，它是最後的依據。
> - **`knowledge/` 知識**：我整理出來的一頁一頁，彼此連起來。你看，我寫。
> - **`knowledge/AGENTS.md` 規格**：這個知識庫怎麼維護的規矩。沒有它，我每次整理的格式都不一樣。
>
> 跟你平常把檔案丟給 AI 最大的差別：那樣每問一次，它就從頭找一次。這裡是**整理過一次就留下來，而且越用越厚**。

**這段一定要先講給他聽，再動手。** 建 `raw/`、`knowledge/topics/`，然後**直接寫**下面三份（不用問他格式；已經存在就只補缺的，不要覆蓋）：

`knowledge/AGENTS.md`：

```markdown
# 這個知識庫怎麼維護

方法：Karpathy 的 LLM Wiki。

## 三層
- `../raw/`：原料。只進不改，不要動、不要刪。
- 本資料夾：我整理的頁面，用 `[[頁名]]` 互相連結。
- 本檔案：規格。

## 三個動作
- **放進來（Ingest）**：一次一份。先問收料三問，寫成一頁，更新相關頁面、`index.md`、`log.md`。
- **問問題（Query）**：先讀 `index.md`，再打開需要的頁面。回答要附出處；頁面沒有的就說不知道。好的答案問他要不要存回來。
- **整理（Lint）**：他說「整理第二大腦」時，檢查互相矛盾、過期內容、沒有被連到的頁面、`raw/` 裡還沒讀的。查完只報告，他點頭才改。

## 一頁長什麼樣
- 開頭寫：`來源`、`讀於`（日期）
- **為什麼讀這個**：他的原話
- **內容重點**：我整理的，條列，不要整份重抄
- **他的看法**：他的原話，一個字不改
- **我補充的**：我讀完發現、他沒提到的
- **連到**：`[[相關頁面]]`

## 建新頁還是併舊頁
已經有這個主題就併進去，註明日期。新主題而且之後還會碰到才建新頁。一次性的雜訊不建頁。

## 目錄與日誌
- `index.md`：每頁一行，`- [[頁名]] — 一句話`。
- `log.md`：只往下加，`- YYYY-MM-DD 放進／更新了 [[頁名]]：一句話`。
```

`knowledge/CLAUDE.md`（只有這一行）：

```markdown
@AGENTS.md
```

`knowledge/index.md`：標題寫「目錄」，先放 `- [[knowledge-map]] — 我的工作需要哪些知識、各在哪裡`。`knowledge/log.md`：標題寫「日誌」。

## 第 7 步 · 放進來（Ingest）

把第 5 步選的檔案**複製一份**進 `raw/`，檔名用英文小寫加連字號：

```bash
# Mac
cp "原檔路徑" "raw/english-name.xlsx"
```

```powershell
# Windows
Copy-Item "原檔路徑" "raw\english-name.xlsx"
```

**他選的是腦袋裡的知識**：當場問他 3–5 題，把他的回答**逐字**存成 `raw/interview-主題.md`，再往下做。

**你讀不動這個檔案**（掃描成圖片的 PDF、缺工具的 Word 或 Excel）：直接說「這份我讀不動」，請他另存成文字版，或換一份。不要自己裝東西，也不要假裝讀過。

讀之前問收料三問（一次一題）：

1. **這是什麼、哪裡來的？** 你先猜，他確認。還要問：這是最新版嗎？
2. **你為什麼想讓我讀它？** 他想拿來做什麼
3. **你自己對它有什麼想法？** 哪裡最有用、哪裡過時了、哪裡寫的跟實際不一樣

第 3 題講一句為什麼，他說不出來就寫「待補」，不要追問：

> 內容重點誰都整理得出來，**你的看法只有你有**。這才是第二大腦裡最值錢的部分。

照規格寫成 `knowledge/topics/頁名.md`，更新 `index.md`、`log.md`。**內容要跟原料對得上，不確定的標「待確認」，不要自己補。**

## 第 8 步 · 問問題（Query）

請他問一題**只有讀過這份資料才答得出來**的問題。你先提議兩題，讓他選或自己問。

回答要附出處（哪一頁、來自哪個原料）。頁面沒有的就說不知道。

然後問他：

> 這個答案對嗎？不對的地方跟我說，我改頁面。這個答案之後還用得到的話，我存回第二大腦，它就會越用越厚。

他說不對，就改頁面，不要辯。

## 第 9 步 · 接回 AGENTS.md（給他看再寫）

在根目錄 `AGENTS.md` 最後加一段，**只加這兩行**：

```markdown
## 我的第二大腦
- 回答跟工作有關的問題前，先查 `knowledge/index.md`，再打開需要的頁面；查不到就說不知道，不要自己編
- 我說「放進第二大腦」或「整理第二大腦」時，照 `knowledge/AGENTS.md` 做
```

動手前先跟他說要加這兩行，他說可以再寫。講一句為什麼：

> 知識不放進 `AGENTS.md`，因為它每次都會整份讀，會越來越慢。這裡只留一句指路，真正的內容要用才查。

## 收尾

把地圖的「下一步」更新成下一份要做的原料。在今天的日記 `memory/daily/[今天日期].md` 接上一段（不要動前面的內容）：

```markdown
## 第二大腦
- 目標：[Q1]
- 做了：[知識地圖；第幾頁知識]
- 下一份要放：[哪一份]
```

然後跟他說：

> 你現在有了：
> - `knowledge/knowledge-map.md`：你的知識地圖
> - `knowledge/topics/[頁名].md`：第一頁。打開看「他的看法」那一區，那是你講的話，我一個字沒改
> - `raw/`：原始檔案，原檔也還在原來的地方
>
> 試試看：開一個**新對話**，問我剛剛那題，看我答不答得出來。
>
> 之後你只要說「**把這份放進第二大腦**」，我就會問你那三題，一次一份。想看它們怎麼連起來，可以用免費的 Obsidian 打開 `knowledge/` 資料夾，看關係圖。

到這裡就結束。不要提 git、備份或要裝什麼。
